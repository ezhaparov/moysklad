# Лендинг: внедрение МойСклад

Сайт собран на React + Vite. Админки нет: **весь контент лежит в одном файле `src/content.ts`**.
Вы правите текст → собираете сайт одной командой → заливаете папку `dist` на хостинг.

## Где что менять

| Что нужно | Где |
|---|---|
| WhatsApp, Telegram, Instagram, телефон, email | `src/content.ts` → раздел 1 `contacts` |
| Имя, заголовок вкладки | раздел 2 `site` |
| Порядок блоков, скрыть блок | раздел 3 `sectionOrder` (переставьте строки или удалите строку) |
| Цены и тарифы | раздел 11 `pricing` (поле `price`) |
| Цифры под первым экраном ([N]) | раздел 5 `hero.stats` |
| Кейсы | раздел 10 `cases` (фото кладите в папку `public/`) |
| Ваше фото и рассказ | раздел 12 `about` (фото в `public/`, например `photo: '/me.jpg'`) |
| FAQ | раздел 13 `faq` |
| Цвета, шрифты, отступы | `src/index.css` |
| Вёрстка блоков (если нужно менять структуру) | `src/App.tsx` |

Правила: меняйте только текст внутри кавычек `'...'`. Запятые, скобки и названия слева (`title:`, `text:`) не трогайте.
В WhatsApp номер пишется цифрами без `+` и пробелов: `'996555123456'`. В Telegram — имя без `@`.

Пока контакты пустые, кнопки ведут к форме внизу. Форма не требует сервера: после заполнения открывается WhatsApp с готовым сообщением (имя, телефон, тип бизнеса).

## Как собрать и выложить

Один раз установите Node.js (nodejs.org, версия LTS). Дальше в папке проекта:

```
npm install      # один раз
npm run dev      # просмотр на своём компьютере, обновляется при правках
npm run build    # сборка: появится папка dist
```

Содержимое папки `dist` загрузите на хостинг (корень сайта). Подойдёт любой обычный хостинг, а также бесплатные Netlify, Vercel, Cloudflare Pages или GitHub Pages: серверная часть и база данных не нужны.
В архиве уже лежит готовая `dist` с заглушками, её можно залить для проверки.

Чтобы изменить сайт позже: поправили `src/content.ts` → `npm run build` → заново залили `dist`.

## Про админку /admin

Не делал намеренно. Чтобы правки из админки сразу появлялись на живом сайте, нужен сервер с базой данных или headless CMS (Strapi, Directus и т.п.), а значит платный хостинг с Node.js и защита входа. Для одностраничного лендинга это лишняя сложность и риск. Если позже захотите, `content.ts` можно перенести в CMS без переделки вёрстки.
Пароль для админки в код не вшивать: хранить его надо только на сервере, в переменных окружения.

## Честно про заглушки

Цифры, цены, кейсы и отзывы оставлены как `[N]`, `[цена]`, `[заглушка]`. Впишите реальные данные, выдуманные не публикуйте.
